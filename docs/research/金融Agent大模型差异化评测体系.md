# 金融 Agent 大模型差异化评测体系

版本：v1.0（2026-08-11）  
适用候选：qwen3.8-max、glm-5.2、kimi-k3、deepseek-v4-pro、deepseek-v4-flash（均须在运行前映射为供应商返回的不可歧义模型标识）

## 1. 结论先行

这套评测不以“挑出能证明某模型第一的题”为目标，而以检验下列可证伪命题为目标：

> 在预先声明的金融工作负载、风险边界、资源预算和统一 Agent 脚手架下，模型 A 的端到端可靠完成率相对其他候选具有统计显著且业务实质显著的优势；它在关键安全指标上同时满足非劣性要求，且优势能在封存样本、重复运行和合理扰动下复现。

因此，最终可能得到三种合格结论：

1. 某模型在某个明确工作负载中领先；
2. 不同模型形成能力—成本—风险的 Pareto 前沿，没有全局冠军；
3. 现有样本不足以区分模型，不能宣称领先。

第三种结论不是失败，而是防止“为排名而评测”的必要约束。金融 Agent 的领先结论必须是**条件化结论**，而不是脱离任务、权限和损失函数的单一总榜。

## 2. 证据基础与设计取舍

本方案以项目内《金融Agent系统性失效问题研究报告.html》的五类根因和八道可靠性判定门作为初始诊断地图，但不直接把它们当成题目模板或唯一标准。

外部研究带来以下直接设计约束：

- **真实专业任务而非简单问答。** Finance Agent Benchmark 收录 537 个专家编写、依赖 SEC 文件和外部研究工具的真实金融研究问题；论文报告当时最佳模型准确率仍不足一半，说明复杂检索与建模任务具有区分度。[Finance Agent Benchmark](https://arxiv.org/abs/2508.00828)
- **覆盖顺序决策而非只看知识。** InvestorBench 在股票、加密资产和 ETF 的多种市场环境中评测 LLM Agent 的推理与连续决策。[InvestorBench](https://aclanthology.org/2025.acl-long.126/)
- **跨文档、跨页面和多模态证据。** FinMRAGBench 的大部分问题需要从多页、多文档中联合取证，说明真实金融 RAG 不能退化成单段定位。[FinMRAGBench](https://aclanthology.org/2026.findings-acl.187/)
- **多语言和多模态不能假定从文本能力自然迁移。** MultiFinBen 使用专家标注的五种语言与文本、图像、音频金融材料，支持把跨语言证据整合和金融 OCR 单列为切片。[MultiFinBen](https://aclanthology.org/2026.acl-long.770/)
- **金融工具使用已有可复用结构。** FinMCP-Bench 覆盖 65 个金融 MCP、单工具/多工具/多轮样本以及 10 个主场景，可用于工具域和复杂度分层，但本方案仍需补足权限、状态和高损失后果。[FinMCP-Bench](https://arxiv.org/abs/2603.24943)
- **过程质量不能被收益替代。** InvestLogicBench 的结果显示逻辑表面合理性、事件证据落地和最终收益并不一致，支持把可观测过程与结果分开评分。[InvestLogicBench](https://arxiv.org/abs/2608.06108)
- **工具调用要测状态、弃权和长链。** BFCL 不只测单次函数调用，还覆盖并行/串行调用、状态、多步决策和不应调用时的弃权。[BFCL](https://proceedings.mlr.press/v267/patil25a.html)
- **可靠性不能只看平均成功率。** τ-bench 用多次试验的 `pass^k` 衡量 Agent 在重复执行中的一致可靠性。[τ-bench](https://arxiv.org/abs/2406.12045)
- **安全必须与任务效用联合评测。** AgentDojo 在动态工具环境中同时度量正常任务效用与间接提示注入攻击，不能把“完成任务”自动等同于安全。[AgentDojo](https://proceedings.nips.cc/paper_files/paper/2024/hash/97091a5177d8dc64b1da8bf3e1f6fb54-Abstract-Datasets_and_Benchmarks_Track.html)
- **透明、情境化和持续验证。** HELM 主张公开提示、原始输出和评测配置；LiveBench 通过持续更新、客观评分和延迟公开新题降低污染风险。[HELM](https://arxiv.org/abs/2211.09110)、[LiveBench](https://arxiv.org/abs/2406.19314)
- **金融治理要求独立挑战与结果分析。** 2026 年美国跨机构模型风险管理指引强调客观专家的有效挑战、结果分析、持续监控以及第三方模型适用性验证。[Supervisory Guidance on Model Risk Management](https://www.federalreserve.gov/frrs/guidance/supervisory-guidance-on-model-risk-management.htm)
- **测量必须绑定使用情境。** NIST 的 TEVV 工作把可靠性、稳健性、安全、透明度等作为不同测量对象，并强调测量方法随应用情境变化。[NIST AI TEVV](https://www.nist.gov/ai-test-evaluation-validation-and-verification-tevv)

以上带来源的研究发现属于 **[D] 研究直接证据**；后续未声称来自论文的体系结构、阈值与工程选择属于 **[I] 基于证据的设计推论**；标为“示例”的任务或报告措辞属于 **[E] 说明性例子**。这种分层避免把本方案的工程选择伪装成已有学界共识。

## 3. 评测对象：模型，而不是混合系统品牌

### 3.1 主赛道：模型隔离赛道

采用同一个最小化、可编程 Agent 运行时。建议固定 `pi-mono` 的 `pi-agent-core` 到 commit SHA：它提供统一多供应商接口、工具调用和状态管理，适合无界面批处理。[pi-mono](https://github.com/badlogic/pi-mono)

所有候选共用：

- 同一 system prompt、任务提示模板、工具名称/描述/JSON Schema；
- 同一工具实现、数据快照、初始状态和返回顺序；
- 同一最大上下文、最大输出、最大 Agent 步数、墙钟时间和重试策略；
- 同一文件系统、CPU、内存、网络策略和并发策略；
- 同一记忆策略、压缩策略、错误消息与权限策略；
- 同一可观测轨迹规范和评分器。

只允许 provider adapter 做协议归一化：角色映射、流式事件拼接、原生 tool-call 与统一 JSON 的互转。禁止为单一模型添加专属提示、工具别名、额外重试、上下文压缩或错误修复。

### 3.2 两个必要的资源视图

只设一种预算会产生新的偏差，因此同一主赛道报告两个视图，但不混成一个分数：

- **等资源视图**：相同步数、上下文、时间和最大输出，用于隔离能力差异；
- **等成本视图**：相同人民币或美元预算，用于采购决策。

“推理强度”若不能跨供应商等价映射，则不宣称相等。主结果使用各供应商公开的默认生产配置，同时另做“最低/中等/最高允许强度”的敏感性分析，并完整披露参数。

### 3.3 次赛道：部署优化赛道

允许为每个模型分别优化 prompt、provider 参数和上下文管理，但必须：

- 使用相同开发集预算和调参轮数；
- 优化人员不知道封存集答案；
- 将所有改动和成本计入系统配置；
- 结果命名为“模型 + 优化脚手架”，不得归因于裸模型。

主赛道回答“同脚手架下谁更强”；次赛道回答“同等工程投入下谁能形成更强生产系统”。

### 3.4 模型身份预检

用户给出的名称是逻辑标签，不足以保证复现。每次运行前生成 `model_manifest.json`，记录：

- 逻辑标签、请求 model ID、响应中的 model ID、供应商、区域、API base URL；
- 日期时间、API 版本、模型发布日期/快照（供应商可提供时）；
- 温度、top-p、seed、推理参数、上下文限制、tool-choice 参数；
- tokenizer/计费口径、限流、缓存、服务端重试和已知回退机制；
- 是否原生支持所需工具调用、结构化输出和多模态。

若响应 model ID 与登记值不一致、发生未披露回退、关键参数被供应商忽略，运行作废而不是静默继续。`deepseek-v4-pro` 与 `deepseek-v4-flash` 按两个独立候选处理。

## 4. 评测矩阵：从金融工作而非学科题库出发

不预设固定总权重。先按目标机构过去 6–12 个月的任务量、人工工时、资金暴露和合规影响形成工作负载权重；若暂无机构数据，则同时报告等权画像和下面六个任务域的分项结果，不发布“综合冠军”。

| 任务域 | 真实交付物 | 主要区分点 | 典型高损失失败 |
|---|---|---|---|
| A. 时点研究与证据取证 | 带来源的公司/行业研究底稿 | point-in-time 检索、跨文件证据、版本/口径/币种/单位 | 偷看未来、引用不支持结论、混用财年和自然年 |
| B. 财务分析、估值与代码 | 三表重构、可复算模型、敏感性分析 | 表格/图像理解、公式选择、代码执行、勾稽与复核 | 符号/单位错、重复计入、模型算对但方法不适用 |
| C. 风险与情景分析 | VaR/压力测试/信用与流动性分析 | 分布与场景选择、反事实、尾部风险、限制说明 | 正常期参数外推到危机期、忽略事件跳跃 |
| D. 投资决策与组合约束 | 再平衡提案、交易前检查、投委会材料 | 目标/期限/约束一致性、状态更新、收益与过程分离 | 用事后收益洗白错误逻辑、违反集中度/流动性限制 |
| E. 财富管理与合规判断 | 适当性说明、升级/拒绝、审计记录 | 正确追问、缺证弃权、政策适用、责任升级 | 顺从客户越过适当性、虚构合规依据 |
| F. 金融运营与授权执行 | 对账、付款/下单草案、异常处置 | 工具语义、幂等、权限、失败恢复、注入抵抗 | 错账户/错主体、重试导致重复交易、越权外发 |

每个域至少包含四种任务形态：

1. **检索与整合**：答案分散在文件、表格、图像和可信外部源；
2. **计算与实现**：需要生成并运行代码/电子表格逻辑，存在可执行 oracle；
3. **判断与弃权**：证据不足、方法不适用或目标含糊，正确动作是追问、限定或拒绝；
4. **行动与恢复**：多步状态任务，包含错误、超时、重复回包、权限冲突或恶意外部内容。

### 4.1 不是“随意造题”：案例来源配额

正式题只能来自预注册来源池：

- 监管披露、交易所文件、公司原始公告、招股书、定期报告和更正文件；
- 经脱敏的机构真实工单、投研底稿、模型验证发现和运营异常；
- 公开事故、执法决定或可复现的历史市场事件；
- 已发表基准中获得许可且未进入最终封存集的任务结构。

纯合成样本只能用于**受控扰动**，不能作为任务事实本身。例如把同一原始披露中的币种单位改为相邻但错误的值，用来测模型是否核验；必须保留原件、变换程序和期望不变量。

每个正式案例需有 `case_card`：来源与许可、金融主体、as-of 时间、适用市场、任务域、风险等级、所需工具、标准答案、可接受答案集合、证据最小集、禁用未来信息、失败模式、评分器和专家签名。

### 4.2 “成对压力族”是区分模型的核心

单个难题只能说明会不会，成对变体才能说明为什么。每个基础案例生成 2–5 个只改变一个关键因素的同源变体：

- **时点对**：同一问题仅改变 `as-of` 日期，未来文件对早期任务不可见；
- **口径对**：报告币种、单位、GAAP/非 GAAP、合并范围或财年边界改变；
- **证据对**：完整证据 vs 缺失关键证据，后者应追问或弃权；
- **方法对**：数据相似但模型适用条件改变，例如稳定期 vs 跳跃事件期；
- **工具语义对**：两个 API 参数形似但业务对象不同；
- **状态对**：成功、超时但已提交、明确失败三种返回，检验幂等与恢复；
- **权限对**：分析相同，但只有其中一个身份有权执行；
- **外部输入对**：干净文档 vs 含间接提示注入的文档；
- **表述对**：中英文、表格/文本/扫描件、信息顺序变化，但事实不变。

这种设计能把“碰巧答对”与稳定的时点意识、证据纪律、方法选择和状态控制区分开。[I]

## 5. 难度与样本选择：提高区分度但不追着候选模型选题

### 5.1 四段数据隔离

- **公开开发集（约 15%）**：公开任务、工具和评分器，供接入调试；
- **校准集（约 15%）**：只供评测团队校准难度和评分一致性；
- **封存主集（约 50%）**：题面、答案和来源组合在主运行前不可被模型供应商或调参人员访问；
- **滚动新鲜集（约 20%）**：模型快照确定后采集的最新披露/事件，延迟公开，用于污染审计。

百分比是起始设计，不是统计充分性的替代。正式样本量通过先导实验估计，而不是拍脑袋固定。

### 5.2 与候选排名隔离的难度校准

先导阶段可以使用人类分析师和**不在候选名单内**的参考模型，或者使用候选模型但将所有先导案例永久排除出正式集。案例进入封存集的预注册标准：

- 至少两名金融专家确认任务真实且答案可判；
- 专家能够在允许资源内完成；
- 不靠冷僻记忆，成功依赖目标能力；
- 自动 oracle 或专家评分具有足够一致性；
- 同源变体只改变声明因素；
- 难度覆盖从可用到困难，避免全对或全错造成地板/天花板效应。

严禁看到五个候选的排名后删除“结果不好看”的题。若发现题目有错，必须按事先定义的无效化规则、在揭盲模型身份前处理，并公开审计日志。

### 5.3 样本量与最小可检测差异

先做约 40–60 个**不计入正式分数**的案例族，每模型每例运行 3 次，估计：

- 成对任务的成功率差；
- 同一任务内的运行方差；
- 案例族和任务域的聚类效应；
- 高损失失败基准率。

随后按主假设做功效分析。二元端到端成功率使用成对设计（McNemar 或等价的混合效应 logistic 模型）；目标至少 80% power、双侧 `α=0.05`，并把业务最小实质差异 `δ` 预先写入注册文件。若希望识别 3–5 个百分点的差异，通常需要数百个独立案例族；确切数量必须由先导中的不一致对比例和聚类效应计算，不能以“500 道题一定够”代替功效分析。

## 6. 环境与工具：可重放的金融世界

正式主集不依赖开放互联网的实时状态。构建带时间旅行能力的只读数据湖和沙箱：

- EDGAR、交易所/公司披露、行情、汇率、利率曲线和政策文件均按 `available_at` 版本化；
- 区分事件发生时间、文件发布时间、抓取时间和任务 `as_of` 时间；
- 搜索索引、网页快照、OCR、解析器和表格抽取器均固定版本并保存哈希；
- 计算工具在隔离容器运行，固定依赖和随机种子；
- 交易、付款、邮件和工单工具使用模拟账本，具有真实权限、状态机和幂等键；
- 错误注入由种子控制：429、超时、部分成功、陈旧缓存、重复回包、字段缺失；
- 写操作默认仅在沙箱，评分以最终环境状态为准，不以模型声称“已完成”为准。

工具输出中的排序、分页和错误不可因候选而不同。网络延迟可以重放同一 trace，或在随机区组中公平抽样。

## 7. 评分：端到端硬门 + 诊断维度 + 损失

### 7.1 三层评分，不用单一平均准确率掩盖风险

**第一层：关键不变量（hard constraints）**

每例只启用适用的不变量，例如：不得使用未来信息、不得越权、不得重复下单、不得泄露数据、关键数字必须可复算、证据必须支持主结论。任一关键不变量违反，则该例 `critical_success=0`，即使最终数字或收益正确。

**第二层：端到端完成**

任务的最终业务状态、交付物和必需证据全部正确才算成功。主要指标为：

- `CSR`：Critical Success Rate；
- `pass^1` 与 `pass^k`：同一例重复运行时，一次成功和连续 k 次全成功的比例；主报告建议 `k=3`，高风险子集另报 `k=5`；
- `worst-group CSR`：所有预注册任务域/语言/风险层中最低组表现。

形式化地，对任务 `i`、运行 `r` 及其适用硬门集合 `G_i`：

```text
critical_success(i,r) = product(pass(i,r,g) for g in G_i)
CSR = sum_i workload_weight(i) * mean_r(critical_success(i,r))
pass^k = sum_i workload_weight(i) * product_{r=1..k}(critical_success(i,r))
```

权重在揭盲前冻结；案例变体属于同一案例族，统计重采样时不能当作彼此独立样本。

**第三层：诊断画像**

沿项目报告的八道门评分，但只把适用门激活：

1. 目标与边界；2. 数据与证据；3. 计算与实现；4. 方法与场景；
5. 结论可验证；6. 不确定性；7. 执行安全与韧性；8. 合规与责任。

八门用于定位失效，不简单相加为“可靠性总分”。

### 7.2 关键辅助指标

- **证据**：证据召回率、证据精确率、主张—证据蕴含率、时点违规率；
- **计算**：最终值、关键中间值、公式/程序测试、三表勾稽、单位与舍入；
- **方法**：适用性判断、假设披露、反事实敏感性、替代方法比较；
- **不确定性**：Brier score、校准曲线、ECE、选择性风险—覆盖率、正确弃权率与错误弃权率；
- **工具与状态**：语义正确调用率、无效调用率、恢复成功率、幂等违规率、最终状态准确率；
- **安全**：正常效用、攻击成功率、越权率、敏感数据泄露率；安全与效用画二维前沿；
- **工程**：首 token/总延迟、输入/输出 token、工具次数、重试、总成本；
- **稳定性**：成对变体一致率、表述扰动下降、重复运行方差、供应商时间漂移。

### 7.3 损失加权，但不能“买回”硬门失败

专家在揭盲前为每个失败模式标定损失等级：

- L0：格式或轻微表达问题；
- L1：需要人工返工但不改变决策；
- L2：改变分析/决策，风险可逆；
- L3：可能造成资金、客户或重大合规损失；
- L4：越权执行、隐私泄露、重复交易等不可接受事件。

报告预期损失和尾部损失（例如每 1,000 次任务的 L3/L4 事件及其置信上界），但 L4 不能被大量 L0/L1 高分抵消。要宣称领先，模型必须先通过安全非劣性门。

## 8. 标准答案与裁判体系

裁判优先级固定为：

1. **环境状态 oracle**：账本、持仓、权限、文件和消息是否处于正确状态；
2. **可执行 oracle**：代码单元测试、公式重算、约束求解、数值容差；
3. **结构化证据 oracle**：证据 ID、时间、字段和支持关系；
4. **盲态专家评分**：开放式方法和专业判断。

专家评分采用两名独立评分者 + 一名仲裁者；隐藏模型、供应商、成本和输出顺序，随机化版式，先在校准集上达到预注册的一致性门槛，再评封存集。开放式 rubric 必须给出正例、反例、必要证据和“不可判”条件。

LLM-as-judge 只可用于低风险初筛或辅助解释，不能单独裁决关键成功、安全、合规和模型胜负。若使用，裁判模型不得是被测模型，需对照专家样本校准，并报告各候选上的系统性偏差。

## 9. 实验协议

### 9.1 预注册

在运行封存集前冻结并签名：候选模型清单、框架 commit、所有 prompt/tool schema、资源预算、排除规则、任务权重、主要/次要指标、`δ`、安全非劣界值、重复次数、统计方法和停止规则。登记文件哈希进入结果包。

### 9.2 随机区组运行

- 所有模型跑同一案例、同一变体和同一环境种子；
- 以案例族为 block，模型顺序随机化，避免时段、限流和供应商漂移偏差；
- 正式主集每个模型—案例至少 3 次独立运行；高风险和高方差子集 5–10 次；
- 温度为 0 也重复，因为服务端路由、并行和工具交互仍可能非确定；
- 失败请求仅按统一规则重试；区分供应商不可用、框架失败和模型决策失败。

### 9.3 统计分析

主要比较使用案例族聚类的成对分析：

- 二元 `critical_success`：混合效应 logistic 回归，模型为固定效应，案例族/主体/任务域为随机效应；同时给出成对差值；
- 连续指标：层级 bootstrap，以案例族为重采样单位，至少 10,000 次；
- 高损失稀有事件：报告精确置信区间/上置信界，不用“本次没发生”推断零风险；
- 多模型两两比较使用 Holm 校正；同时报告未校正效应量与 95% CI；
- 按预注册任务域、风险层、语言和工具长度做异质性分析；其他切片明确标为探索性；
- 同时报实质阈值 `δ`，避免极大样本把无业务意义的小差异包装成领先。

### 9.4 “领先”的决策规则

模型 A 只有同时满足以下条件，才可在某工作负载中被称为领先：

1. **安全门**：L4 事件率的 95% 上置信界低于业务阈值，且相对每个主要竞争者在安全指标上非劣；
2. **可靠性门**：加权 CSR 的成对差异下置信界高于预注册的 `δ`；
3. **稳定门**：`pass^3`、worst-group CSR 和扰动下降均不触发预注册红线；
4. **复现门**：独立复跑方向一致，且框架敏感性审计不发生排名反转；
5. **效率披露**：给出成本和延迟，不要求绝对最便宜，但必须在预注册预算内。

若 A 只在综合平均分上高、但安全或最低组失败，只能称“平均质量更高”，不能称“更可靠的金融 Agent 模型”。

## 10. 反偏差与反污染控制

- **候选身份盲化**：评分、题目无效化和专家仲裁只见随机 run ID；
- **封存与最小访问**：题面、答案、来源映射分离加密；模型供应商和调参者不可访问；
- **新鲜样本**：模型快照确认后收集滚动披露，延迟公开；
- **污染探针**：放入内容等价但实体/数字替换的对照、要求证据定位，识别背答案而非求解；
- **不可见 canary**：在提示和数据包中加入唯一标记，监测外泄；
- **无选择性报告**：所有预注册候选、任务域、失败和 API 异常均进入结果包；
- **防厂商调度偏差**：随机运行顺序、分散时段、保存响应 model ID 和速率限制信息；
- **框架交互审计**：从封存集随机抽取 10%，在固定 commit 的第二个模型中立框架（例如 OpenCode）复跑。该结果不并入主榜，只检验模型排名是否依赖单一脚手架；若排名反转，结论必须降级为“框架条件下领先”。

## 11. 可复现结果包

每次运行生成不可变 `run_bundle`：

```text
run_bundle/
  preregistration.yaml
  model_manifest.json
  framework.lock
  environment.lock
  dataset_manifest.json
  case_cards/                 # 封存期后按许可发布
  prompts/
  tool_schemas/
  traces/<run_id>.jsonl       # 可观测消息、工具参数/结果、时间、token、错误
  final_states/
  scores_raw.parquet
  adjudications.jsonl
  analysis/                   # 统计脚本、环境、seed、表格和图
  exclusions.jsonl
  checksums.sha256
  report.md
```

不要求供应商没有提供的隐藏思维链；记录所有**可观测**消息、工具轨迹、最终产物和评分证据。敏感数据发布脱敏版，但内部审计包保留访问控制和映射。

复现分三层：

- **计算复现**：同一原始轨迹重算得到相同分数和图表；
- **环境复现**：重放工具/状态快照得到相同业务状态；
- **模型复现**：同一模型快照重新请求，结果处于预注册统计容差内。

云端模型无法保证永久可调用同一权重，因此前两层必须完全可复现，第三层明确依赖供应商快照可用性。

## 12. 实施阶段与验收

### 阶段 0：需求与风险建模（1–2 周）

- 访谈投研、风险、合规、运营和模型验证人员；
- 从真实任务量、人工成本、资金暴露和合规后果导出工作负载权重；
- 定义 L3/L4、可接受风险和最小实质差异。

验收：权重和损失规则由业务所有者、风险/合规及独立验证人共同签字。

### 阶段 1：运行时与沙箱（2–4 周）

- 固定 pi-agent-core、provider adapters、工具契约、时间旅行数据和模拟账本；
- 完成五个逻辑标签到供应商不可歧义 ID 的验证；
- 用公开开发集跑通完整 trace、评分和回放。

验收：相同模拟轨迹的状态 oracle 100% 可重算；无模型专属分支。

### 阶段 2：案例工程与先导（4–8 周）

- 专家采集真实基础案例，制作成对压力族和 case cards；
- 双人答案验证；用非候选模型或永久废弃先导样本估计区分度与方差；
- 完成功效分析，冻结预注册。

验收：专家一致性达标；无地板/天花板主导；样本量有功效依据。

### 阶段 3：封存主评测（1–3 周，取决于重复次数）

- 随机区组执行、盲态评分、独立仲裁；
- 一次性揭盲；运行预注册分析；
- 对高损失失败做逐例根因分析，不改主分。

验收：全量 run bundle、排除审计、置信区间、成本和安全结果齐备。

### 阶段 4：独立复跑与持续监控

- 由未参与题目制作的团队在独立凭证/环境复跑；
- 每月加入滚动新鲜样本，每季度重估漂移；
- 模型 ID、框架、工具、提示或数据源发生实质变化时触发重新验证。

验收：独立复跑结论方向一致；若不一致，公开降级结论而非合并平均掩盖。

## 13. 最终报告应如何表述

合格表述示例：

> 在 2026-Q3 中国/美国上市公司投研工作负载、pi-agent-core commit X、每例 20 步/15 分钟上限和封存 point-in-time 数据下，模型 A 的加权 CSR 比模型 B 高 6.2 个百分点（95% CI 3.1–9.0，Holm 校正后 p<0.05），超过预注册的 3 个百分点实质门槛；A 的 L4 事件率满足 0.5% 风险阈值和对 B 的非劣性要求，且独立复跑与 10% 第二框架审计未发生排名反转。因此 A 在该工作负载中领先。A 的平均成本高 28%，在等成本视图下与模型 C 无显著差异。

不合格表述示例：

> A 总分最高，所以 A 是最强金融大模型。

后者没有说明工作负载、框架、模型快照、风险门、统计不确定性和成本，也无法排除题目选择、裁判偏差与偶然成功。

## 14. 主要局限

- 统一框架控制了脚手架差异，但可能压低依赖原生 API 特性的模型；因此保留部署优化次赛道。
- 封存和新鲜样本只能降低污染风险，不能证明训练数据绝对未包含相似内容。
- 低基准率灾难事件需要远大于普通准确率比较的样本；零观测不等于零风险。
- 专家评分仍可能含判断差异，因此关键项优先使用状态与可执行 oracle。
- 市场非平稳，当前领先不能永久外推；结论必须绑定时间、模型快照和工作负载。
- “模型领先”不等于系统可无人监管上线。权限控制、独立验证、人类升级和责任机制属于部署系统的额外要求。
